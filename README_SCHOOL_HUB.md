# Школьный Хаб

Одностраничное PWA-приложение для школьников: расписание, домашние задания, объявления и общий чат класса. Данные хранятся в Firebase Realtime Database, вся логика — в `index.html`, дополнительные файлы — только манифест и сервис-воркер для PWA.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Все приложение: HTML, стили (Tailwind CDN) и JavaScript |
| `manifest.json` | Манифест PWA (установка на главный экран) |
| `sw.js` | Service Worker (офлайн-кэш) |
| `firebase-config.js` | Конфиг Firebase (нужно вписать свои значения из консоли) |
| `auth.js` | Анонимная авторизация Firebase + профиль `users/{uid}` |
| `moderation.js` | Баны/муты по UID (ветка `bannedUsers/{uid}`) |
| `rules.json` | Готовые правила Realtime Database (можно публиковать целиком) |
| `icon-192.png`, `icon-512.png` | Иконки приложения |
| `README_SCHOOL_HUB.md` | Эта инструкция |

## Возможности

- **Экран входа** — пошаговый выбор: город → школа → класс (списки из Firebase).
- **Запоминание выбора** — город, школа и класс сохраняются в `localStorage`; при повторном заходе класс открывается сразу.
- **Главный экран** — шапка «Город, Школа, Класс» + кнопка «Сменить».
- **Вкладки**:
  - *Расписание* — на сегодня и завтра;
  - *Домашка* — предметы и задания;
  - *Объявления* — лента новостей (закреплённые сверху, с фото и видео);
  - *Чат* — сообщения в реальном времени, ник хранится в `localStorage`, у сообщений показывается время.
- **Объявления от админа** — в режиме администратора во вкладке **«Объявления»** появляется форма «📣 Новое объявление»:
  - текст (до 1000 символов) и **одно вложение — фото или видео**;
  - фото автоматически сжимается через canvas (не шире 1280 px, JPEG 0.72, итог ≤ ~900 КБ) и хранится в базе как data-URL;
  - видео сохраняется как есть, ограничение — **3 МБ**;
  - кнопки **«Опубликовать»** и **«📌 Закрепить»** (опубликовать сразу закреплённым);
  - клик по фото открывает просмотр во весь экран (`#media-modal`, закрытие по `✕`, клику мимо и `Esc`);
  - то же самое доступно в админ-панели → **«Данные» → объявления** (там же «Закрепить/Открепить» и «Удалить» у каждой записи);
  - **удаление**: у каждого объявления у администратора есть кнопка **✕** с подтверждением — и прямо на вкладке «Объявления», и в админ-панели → «Данные» → объявления;
  - если ни одно объявление не закреплено, сверху по старому поведению показывается самое свежее с меткой «📌 ЗАКРЕПЛЕНО».
- **Закрепление сообщений в чате** — у админа у каждого сообщения есть кнопка **📌**. Закреплённые сообщения собираются в блок **«📌 ЗАКРЕПЛЕНО»** над чатом: там кнопка **↓** (прокрутка к сообщению с подсветкой) и **✕** (открепить, только для админа). Само сообщение получает золотистую рамку и метку 📌.
- **Счётчик онлайна в шапке чата** — рядом с кнопкой «Поиск» горит `🟢 N онлайн` (считаются устройства из `/online`, чья отметка присутствия свежее 5 минут). Если таких нет — `🔴 0 онлайн`. Пересчёт идёт по живой подписке и раз в 30 секунд.
- **Аватар-эмодзи** — в «Настройках» блок **«😀 Аватар»**: сетка из 60 эмодзи, кнопки «🎲 Случайный» и «Буква ника» (возврат к первой букве ника). Значение хранится в `users/{uid}/avatar` и подтягивается в чат, в избранное и в админ-панель «Люди».
- **«О себе» (bio)** — в «Настройках» поле до 140 символов. Показывается в карточке профиля, в списке «Люди» (админ) и в **карточке пользователя**, которая открывается тапом по аватару в чате (там же ник, класс и галочка админа). Хранится в `users/{uid}/bio`.
- **Обратный отсчёт до конца урока**:
  - липкая плашка под верхней навигацией и карточка на вкладке «Расписание»: **«До конца урока: Математика 12:34»** с полосой прогресса (за 5 минут до конца полоса краснеет), либо **«До урока: …»**, либо **«Уроки закончились»** / **«Сегодня уроков нет»**;
  - расписание звонков лежит в `classes/{class}/lessons` — массив строк вида `"08:00-08:45"`; если ветки нет, используются стандартные 7 уроков;
  - редактируется в админ-панели → **«Данные» → Звонки**: начало и конец каждого урока, кнопки «+ Урок», «Сохранить», «Вернуть стандартные», «Очистить»;
  - отсчёт показывается только в дни, когда в расписании на текущий день есть хотя бы один урок.
- **Тема `coder20`** — третий вариант оформления в «Настройках» (рядом с тёмной и светлой):
  - **всё становится серым** — фильтр `grayscale(1)` навешивается на прямых потомков `body` (не на `html`/`body`, чтобы не сломать `position: fixed` у модалок и тостов); при этом кружки выбора цвета акцента остаются цветными, иначе их не различить;
  - **приложение смещается влево** — колонка интерфейса прижимается к левому краю окна, справа освобождается место под циферблат;
  - **«обруч» с временем и датой** — круглый циферблат в освободившейся правой части: кольцо-трек, 12 часовых засечек, дуга-индикатор хода секунд внутри текущей минуты, а внутри — **время `ЧЧ:ММ`**, секунды и дата в формате «26 сентября, суббота». Часы тикают раз в секунду только пока активна тема `coder20`, при возврате на вкладку циферблат обновляется сразу;
  - раскладка включается от **600 px** ширины окна: на узких телефонах места «сбоку» нет, поэтому интерфейс остаётся во всю ширину, а циферблат скрыт;
  - тема запоминается в `localStorage` (`sh_theme` = `dark` | `light` | `coder20`) и применяется до первой отрисовки — без мигания; цвет системной строки состояния тоже становится серым (`#111827`).
- **Галочка администратора** — у ника админа в чате зелёная галочка **✓**. Список админов: `roles/{uid} === 'admin'`, `admins/{uid} === true` и жёстко зашитый `HARDCODE_ADMIN_UIDS`.
- **Запрещённые фразы в чате** — список `FORBIDDEN_TEXTS` в начале скрипта `index.html` (по умолчанию там пароль админа). Сравнение устойчиво к регистру, пробелам и лишним символам: проверяется отправка, ввод в поле и вставка из буфера.
- **Копирайт** — в самом низу вкладки «Настройки» мелким шрифтом: `Developers: ZakveZ,coder20`.
- **Уведомления** — если появилось объявление с текстом «Завтра контрольная», вверху экрана всплывает toast.
- **Автофильтр сообщений** — мат, оскорбления и угрозы не удаляются, но помечаются флагом (`flagged: true`) и попадают в раздел **«Интересное»** админ-статистики.
- **Авторизация** — при первом заходе происходит анонимный вход Firebase (`signInAnonymously`), пользователь получает стабильный `uid`. Сессия восстанавливается автоматически. `uid` — основной идентификатор пользователя для чата, статистики и банов (вместо `device_id`).
- **Баны и муты** — хранятся в ветке `bannedUsers/{uid}`: `{ until, reason, bannedBy, bannedAt }`. `until` — таймстамп окончания (мс); `0` или отсутствует — бессрочный. Перед отправкой сообщения приложение проверяет бан и блокирует отправку с объяснением.
- **Модерация из «Интересного»** — у каждого помеченного сообщения есть кнопки **«Мут 1 час», «Мут 24 часа», «Разбанить», «Предупредить»** (по автору через `uid`, для старых сообщений — через привязку `device_id → uid`). «Предупредить» не банит, а пишет уведомление в `warnings/{uid}` — пользователь увидит его тостом при следующем заходе.
- **Админ-режим** (скрытый) — добавляет/редактирует города, школы, классы, а также расписание, домашку и объявления для любого класса.
  - Открывается **5 тапами по логотипу** на экране входа или долгим нажатием на заголовок, затем вводится пароль админа.
  - После входа открывается обычный хаб + вкладка **«Настройки»** (только для админа): переключатель «Альт-менедж» (кнопки удаления сообщений прямо в чате) и кнопка «Полная админ-панель».
  - Полная админ-панель: **Города / Школы / Классы / Данные / Люди и чат / Статистика**.
  - **«Статистика»** — счётчики городов, школ и классов; **онлайн** (устройства последние 5 минут), **уникальные** пользователи; **активные классы** (сообщения за 24 часа); раздел **«Интересное»** со всеми помеченными фильтром сообщениями и кнопками: **Открыть чат**, **Мут 1 час**, **Мут 24 часа**, **Разбанить**, **Предупредить**, **Игнорировать**, **Удалить сообщение**.
  - Не требует выбора класса — можно заполнить данные «с нуля».

## 1. Настройка Firebase

1. Зарегистрируйтесь на https://console.firebase.google.com/ и создайте проект.
2. **«Добавить приложение» → Web (`</>`)** — скопируйте объект конфигурации.
3. В меню слева выберите **Realtime Database** (не Cloud Firestore!):
   - «Создать базу данных», укажите регион;
   - режим доступа — **«Тестовый режим»** (для старта; правила ниже).
4. Откройте `firebase-config.js` и вставьте свои значения на место `YOUR_...`. Убедитесь, что `databaseURL` указывает на вашу базу.

### Правила базы (`Realtime Database` → вкладка «Правила»)

Для теста (все открыто) можно оставить `{ "rules": { ".read": true, ".write": true } }`, но рабочая версия — на анонимной авторизации:

1. В консоли Firebase включите **Authentication → Sign-in method → Anonymous → Enable**.
2. В **Realtime Database → Правила** вставьте содержимое `rules.json` целиком и нажмите **Опубликовать**.
3. Сразу после публикации добавьте **свой UID** в ветку `admins` (Data → `+`): `admins/<ваш uid> = true`. UID виден в приложении: **Настройки → «Мой ID»**. Без этого не получится редактировать контент и банить.

Ключевое правило: писать в чат/города может только **авторизованный пользователь, которого нет в `bannedUsers`** (или чей бан истёк). Бессрочный бан (`until = 0`) тоже блокирует запись.

Отдельно: запись в `announcements` (объявления) и в `roles`/`bannedUsers`/`warnings` разрешена **только администраторам** — `roles/{uid} === 'admin'`, жёстко зашитому UID или `admins/{uid} === true`. После изменения `rules.json` правила нужно **переопубликовать** в консоли, иначе на сервере останутся старые.

Пользователь может писать только свои `users/{uid}`: `nick`, `class`, `deviceId`, `avatar`, `bio` (все — с проверкой `$uid === auth.uid`), `createdAt` — только при первом входе. Поля `avatar` и `bio` разрешены пустыми (`""`), так чистится «О себе» и сбрасывается аватар на букву ника.

## 3. Заполнение данных (админ-режим)

Перед заполнением убедитесь, что сделаны шаги из раздела «Правила базы»: включён анонимный вход, опубликованы правила, ваш UID добавлен в `admins`.

1. Откройте приложение.
2. На экране входа **5 раз тапните по логотипу** (или долго нажмите на заголовок) — появится запрос пароля админа.
3. Вкладка **«Города»** — добавьте город.
4. **«Школы»** — выберите город и добавьте школу.
5. **«Классы»** — выберите город и школу, добавьте класс.
6. **«Данные»** — выберите город → школу → класс и редактируйте расписание, домашку и объявления (у объявления — вложение-фото/видео и закрепление).
7. **«Статистика»** — счётчики, онлайн-пользователи и раздел **«Интересное»** с помеченными фильтром сообщениями (там же — модерация авторов по UID).

После этого обычные ученики увидят город/школу/класс в списках выбора.

## 4. Автофильтр сообщений

При отправке сообщения текст проверяется по локальным спискам слов (мат / оскорбление / угроза — регистр не важен). Найденные категории записываются в поле `reason` (например, «мат, угроза»), а само сообщение:
- остаётся в чате (удалять его может только админ),
- помечается флагом `flagged: true`,
- дублируется в ветку `flagged_messages/...`, откуда попадает в раздел **«Интересное»** вкладки «Статистика».

Списки слов находятся в константе `BAD_WORDS` в начале скрипта `index.html` — их легко дополнить/отредактировать.

## 5. Авторизация и баны

### Как включить (консоль Firebase)

1. **Authentication → Get started → Sign-in method → Anonymous → Enable → Save** — без этого приложение покажет тост «Авторизация ещё не готова» и отправка в чат будет заблокирована.
2. Если API-ключ ограничен: **Google Cloud Console → APIs & Services → Credentials** — API restrictions должна включать Identity Toolkit API, а Application restrictions не блокировать ваш домен.
3. Для GitHub Pages домен добавляется в **Authentication → Settings → Authorized domains** (при появлении ошибки `auth/unauthorized-domain`).

### Как работает в приложении

- При первом заходе вызывается `signInAnonymously()`; если пользователь уже входил — сессия восстанавливается сама (`onAuthStateChanged`).
- После входа доступны `auth.currentUser.uid` (через `window.HubAuth.uid`) — `uid` пишется в новые сообщения (`uid`, `nick`, `class`) и в профиль `users/{uid}` (туда же для совместимости кладётся `device_id`).
- Перед отправкой сообщения вызывается `HubModeration.checkCanSend()`:
  - нет записи в `bannedUsers` — отправка разрешена;
  - запись есть и бан не истёк — отправка блокируется: «Ты забанен до [дата]. Причина: [reason]» (при `until = 0` — «Ты забанен навсегда…»);
  - бан истёк — отправка разрешается, а устаревшая запись из `bannedUsers/{uid}` удаляется.
- Ветка `bannedUsers/{uid}`: `{ until, reason, bannedBy, bannedAt }`.
  - `until` — **миллисекунды** (Firebase `now` в правилах тоже в мс): мут 1 ч = `now + 3600000`, мут 24 ч = `now + 86400000`;
  - `until = 0` либо отсутствует — бессрочный бан;
  - «Разбанить» удаляет запись целиком.

### Кнопки модерации в «Интересном»

Рядом с каждым помеченным сообщением в разделе **«Статистика» → «Интересное»**:

| Кнопка | Действие |
|---|---|
| **Мут 1 час** | `bannedUsers/{uid}` c `until = now + 3600000` |
| **Мут 24 часа** | `until = now + 86400000` |
| **Разбанить** | удаляет `bannedUsers/{uid}` |
| **Предупредить** | **без бана**: пишет уведомление в `warnings/{uid}`; пользователь видит его тостом при следующем заходе |

Автор берётся из поля `uid` помеченного сообщения; для старых сообщений (без `uid`) — через привязку `device_id → uid` из профилей `users/{uid}/deviceId`. Если резолв не удался, кнопки неактивны.

Совместимость: старые сообщения с `device_id`/`name` остаются как есть, новые пишутся с `uid`/`nick`; устройство пользователя, заходившего до авторизации, при первом входе связывается с новым анонимным аккаунтом (поле `deviceId` в профиле).

## 6. Локальный запуск

Firebase и PWA не работают с протоколом `file://`, поэтому нужен локальный сервер:

```
python -m http.server 8000
```

или расширение **Live Server** (VS Code). Затем откройте http://localhost:8000

## 7. Деплой на GitHub Pages

1. Создайте репозиторий на GitHub.
2. Залийте файлы (`index.html`, `manifest.json`, `sw.js`, `firebase-config.js`, `index.ico`…, иконки):

```bash
git init
git add .
git commit -m "Школьный Хаб"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/НАЗВАНИЕ_РЕПО.git
git push -u origin main
```

3. В репозитории откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите:
   - **Source**: `Deploy from a branch`
   - **Branch**: `main` / **folder**: `/ (root)`

## Заметки

- Иконки `icon-192.png` и `icon-512.png` — простые PNG; при желании замените на свои.
- При смене версии приложения обновите имя кэша в `sw.js` (сейчас `school-hub-v12`), чтобы новые файлы подхватились.
- Фото и видео объявлений лежат **внутри самой записи объявления** как data-URL (отдельный Storage-бакет не используется), поэтому действуют лимиты Firebase на размер узла — отсюда сжатие фото и лимит 3 МБ на видео.
- Поле закрепления сообщения (`chat/{key}/pinned`) технически доступно любому, кто может писать в чат (так устроены правила `chat`), но кнопка 📌 и обработчик есть только у админа.
- Ник пользователя хранится в `localStorage`, уведомления о «Завтра контрольная» не повторяются для уже просмотренных объявлений.
- Аватар-эмодзи и «О себе» дублируются в `localStorage` (`sh_avatar`, `sh_bio`) и в `users/{uid}`. Локальная запись применяется мгновенно, а синхронизация с базой уходит фоном: если нет прав или нет сети, в интерфейс не попадает текст «Сохранено только на этом устройстве».
- Счётчик онлайна считает **устройства**, а не людей: один человек с двух телефонов даёт «2 онлайн».
- Счётчик считает глобально по ветке `/online`, а не по конкретному классу.
