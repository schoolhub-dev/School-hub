# Школьный Хаб

Одностраничное PWA-приложение для школьников: расписание, домашние задания, объявления, общий чат класса, **личные сообщения** и **голосовые сообщения**. Данные хранятся в Firebase Realtime Database, вся логика — в `index.html`. При первом входе приложение само выдаёт логин и 5-значный пароль и запоминает их на устройстве — вводить их заново не нужно.

## Возможности

- **Экран входа** — пошаговый выбор: город → школа → класс (списки из Firebase).
- **Запоминание выбора** — город, школа и класс сохраняются в `localStorage`; при повторном заходе класс открывается сразу.
- **Главный экран** — шапка «Город, Школа, Класс» + кнопка «Сменить».
- **Вкладки**:
  - *Расписание* — на сегодня и завтра;
  - *Домашка* — предметы и задания;
  - *Объявления* — лента новостей;
  - *Чат* — сообщения в реальном времени, ник хранится в `localStorage`, у сообщений показывается время, есть микрофон для голосовых.
- **Регистрация при первом входе** — приложение само генерирует логин и 5-значный пароль, логин можно поменять до сохранения. Если стоит галочка «Запомнить», данные сохраняются в `localStorage` и последующие входы идут молча, без пароля. Войти с другого устройства можно по логину и паролю — см. [раздел 8](#8-регистрация-и-вход).
- **Личные сообщения (ЛС)** — кнопка ✉️ в шапке открывает полноэкранную панель: список собеседников (одноклассники + те, кто писал в общий чат), поиск, счётчик непрочитанных на кнопке. См. [раздел 9](#9-личные-сообщения).
- **Голосовые сообщения** — кнопка 🎤 рядом с полем ввода в чате и в ЛС. Запись до 60 секунд, opus 16 кбит/с, до 150 КБ. См. [раздел 10](#10-голосовые-сообщения).
- **Темы оформления** — светлая, тёмная и **coder20**: обесцвеченный (grayscale) интерфейс, сдвинутый влево контент и круглые часы с датой на правой стороне экрана. См. [раздел 11](#11-тема-coder20).
- **Уведомления** — если появилось объявление с текстом «Завтра контрольная», вверху экрана всплывает toast.
- **Автофильтр сообщений** — мат, оскорбления и угрозы не удаляются, но помечаются флагом (`flagged: true`) и попадают в раздел **«Интересное»** админ-статистики.
- **Авторизация** — при первом заходе происходит анонимный вход Firebase (`signInAnonymously`), пользователь получает стабильный `uid`. Сессия восстанавливается автоматически. `uid` — основной идентификатор пользователя для чата, статистики и банов (вместо `device_id`).
- **Баны и муты** — хранятся в ветке `bannedUsers/{uid}`: `{ until, reason, bannedBy, bannedAt }`. `until` — таймстамп окончания (мс); `0` или отсутствует — бессрочный. Перед отправкой сообщения приложение проверяет бан и блокирует отправку с объяснением.
- **Модерация из «Интересного»** — у каждого помеченного сообщения есть кнопки **«Мут 1 час», «Мут 24 часа», «Разбанить», «Предупредить»** (по автору через `uid`, для старых сообщений — через привязку `device_id → uid`). «Предупредить» не банит, а пишет уведомление в `warnings/{uid}` — пользователь увидит его тостом при следующем заходе.
- **Админ-режим** (скрытый) — добавляет/редактирует города, школы, классы, а также расписание, домашку и объявления для любого класса.
  - Открывается **5 тапами по логотипу** на экране входа или долгим нажатием на заголовок, затем вводится пароль админа.
  - После входа открывается обычный хаб + вкладка **«Настройки»** (только для админа): переключатель «Альт-менедж» (кнопки удаления сообщений прямо в чате) и кнопка «Полная админ-панель».
  - Полная админ-панель: **Города / Школы / Классы / Данные / Люди и чат / Статистика**.
  - **«Статистика»** — счётчики городов, школ и классов; **онлайн** (устройства последние 5 минут), **уникальные** пользователи; **активные классы** (сообщения за 24 часа); раздел **«Интересное»** со всеми помеченными фильтром сообщениями и кнопками: **Открыть чат**, **Мут 1 час**, **Мут 24 часа**, **Разбанить**, **Предупредить**, **Игнорировать**, **Удалить сообщение**.
  - Не требует выбора класса — можно заполнить данные «с нуля».

## 1. Настройка Firebase

1. Зарегистрируйтесь на https://console.firebase.google.com/ и создайте проект.
2. **«Добавить приложение» → Web (`</>`)** — скопируйте объект конфигурации.
3. В меню слева выберите **Realtime Database** (не Cloud Firestore!):
   - «Создать базу данных», укажите регион;
   - режим доступа — **«Тестовый режим»** (для старта; правила ниже).
4. Откройте `firebase-config.js` и вставьте свои значения на место `YOUR_...`. Убедитесь, что `databaseURL` указывает на вашу базу.

### Правила базы (`Realtime Database` → вкладка «Правила»)

Для теста (все открыто) можно оставить `{ "rules": { ".read": true, ".write": true } }`, но рабочая версия — на анонимной авторизации:

1. В консоли Firebase включите **Authentication → Sign-in method → Anonymous → Enable**.
2. В **Realtime Database → Правила** вставьте содержимое `rules.json` целиком и нажмите **Опубликовать**.
3. Сразу после публикации добавьте **свой UID** в ветку `admins` (Data → `+`): `admins/<ваш uid> = true`. UID виден в приложении: **Настройки → «Мой ID»**. Без этого не получится редактировать контент и банить.

Ключевое правило: писать в чат/города может только **авторизованный пользователь, которого нет в `bannedUsers`** (или чей бан истёк). Бессрочный бан (`until = 0`) тоже блокирует запись.

## 2. Структура базы

```
cities/{city_id}/
  name: "Находка"
  schools/{school_id}/
    name: "Школа №4"
    classes/{class_id}/
      name: "7А"
      schedule: { mon: ["Математика", "Русский язык"], tue: [...], ... }
      homework: { "Математика": "Задание 5", ... }
      announcements: { <key>: { text: "...", createdAt: 1690000000000 } }
      chat: { <key>: { uid, deviceId?, nick, text, time, class, flagged: true? } }
users/{uid}:
  { nick: "Миша", class: "7А", deviceId: "abc-...", createdAt: 1690000000000 }
  // поля аккаунта (пишет только сам владелец uid):
  { uname: "misha_07", unameLower: "misha_07",
    passHash: "<sha256>", salt: "<12 hex>", regAt: 1690000000000 }
unames/{логин в нижнем регистре}:
  { uid: "<чей uid>", at: 1690000000000 }   // глобальный индекс: логин занят ровно одним человеком
dms/{uid}/{uid собеседника}/{<key>}:
  { from: "<uid>", fromNick: "Вася", to: "<uid>",
    text: "Привет", time: 1690000000000, read: true }
  // у каждого своя копия ветки: отправитель пишет и себе, и получателю
  // voice: { url: "data:audio/webm;base64,...", mime, dur, kb } — необязательно
bannedUsers/{uid}:
  { until: 1727356800000, reason: "оскорбление", bannedBy: "admin", bannedAt: 1727270400000 }
  // until в миллисекундах; 0 или отсутствует = бессрочный бан
warnings/{uid}/{<key>}:
  { text: "...", by: "admin", at: 1690000000000 }   // кнопка «Предупредить»
flagged_messages/{city_id}/{school_id}/{class_id}/{message_key}:
  { uid?, deviceId?, nick, text, time, reason, cityName, schoolName, className }   // помеченные сообщения
online/{device_id}: timestamp          // онлайн-присутствие (пишется каждые 30 сек)
unique/{device_id}: timestamp          // учёт уникальных устройств
admins/{uid}: true                     // администраторы (UID из настроек)
```

## 3. Заполнение данных (админ-режим)

Перед заполнением убедитесь, что сделаны шаги из раздела «Правила базы»: включён анонимный вход, опубликованы правила, ваш UID добавлен в `admins`.

1. Откройте приложение.
2. На экране входа **5 раз тапните по логотипу** (или долго нажмите на заголовок) — появится запрос пароля админа.
3. Вкладка **«Города»** — добавьте город.
4. **«Школы»** — выберите город и добавьте школу.
5. **«Классы»** — выберите город и школу, добавьте класс.
6. **«Данные»** — выберите город → школу → класс и редактируйте расписание, домашку и объявления.
7. **«Статистика»** — счётчики, онлайн-пользователи и раздел **«Интересное»** с помеченными фильтром сообщениями (там же — модерация авторов по UID).

После этого обычные ученики увидят город/школу/класс в списках выбора.

## 4. Автофильтр сообщений

При отправке сообщения текст проверяется по локальным спискам слов (мат / оскорбление / угроза — регистр не важен). Найденные категории записываются в поле `reason` (например, «мат, угроза»), а само сообщение:
- остаётся в чате (удалять его может только админ),
- помечается флагом `flagged: true`,
- дублируется в ветку `flagged_messages/...`, откуда попадает в раздел **«Интересное»** вкладки «Статистика».

Списки слов находятся в константе `BAD_WORDS` в начале скрипта `index.html` — их легко дополнить/отредактировать.

## 5. Авторизация и баны

### Как включить (консоль Firebase)

1. **Authentication → Get started → Sign-in method → Anonymous → Enable → Save** — без этого приложение покажет тост «Авторизация ещё не готова» и отправка в чат будет заблокирована.
2. Если API-ключ ограничен: **Google Cloud Console → APIs & Services → Credentials** — API restrictions должна включать Identity Toolkit API, а Application restrictions не блокировать ваш домен.
3. Для GitHub Pages домен добавляется в **Authentication → Settings → Authorized domains** (при появлении ошибки `auth/unauthorized-domain`).

### Как работает в приложении

- При первом заходе вызывается `signInAnonymously()`; если пользователь уже входил — сессия восстанавливается сама (`onAuthStateChanged`).
- После входа доступны `auth.currentUser.uid` (через `window.HubAuth.uid`) — `uid` пишется в новые сообщения (`uid`, `nick`, `class`) и в профиль `users/{uid}` (туда же для совместимости кладётся `device_id`).
- Перед отправкой сообщения вызывается `HubModeration.checkCanSend()`:
  - нет записи в `bannedUsers` — отправка разрешена;
  - запись есть и бан не истёк — отправка блокируется: «Ты забанен до [дата]. Причина: [reason]» (при `until = 0` — «Ты забанен навсегда…»);
  - бан истёк — отправка разрешается, а устаревшая запись из `bannedUsers/{uid}` удаляется.
- Ветка `bannedUsers/{uid}`: `{ until, reason, bannedBy, bannedAt }`.
  - `until` — **миллисекунды** (Firebase `now` в правилах тоже в мс): мут 1 ч = `now + 3600000`, мут 24 ч = `now + 86400000`;
  - `until = 0` либо отсутствует — бессрочный бан;
  - «Разбанить» удаляет запись целиком.

### Кнопки модерации в «Интересном»

Рядом с каждым помеченным сообщением в разделе **«Статистика» → «Интересное»**:

| Кнопка | Действие |
|---|---|
| **Мут 1 час** | `bannedUsers/{uid}` c `until = now + 3600000` |
| **Мут 24 часа** | `until = now + 86400000` |
| **Разбанить** | удаляет `bannedUsers/{uid}` |
| **Предупредить** | **без бана**: пишет уведомление в `warnings/{uid}`; пользователь видит его тостом при следующем заходе |

Автор берётся из поля `uid` помеченного сообщения; для старых сообщений (без `uid`) — через привязку `device_id → uid` из профилей `users/{uid}/deviceId`. Если резолв не удался, кнопки неактивны.

Совместимость: старые сообщения с `device_id`/`name` остаются как есть, новые пишутся с `uid`/`nick`; устройство пользователя, заходившего до авторизации, при первом входе связывается с новым анонимным аккаунтом (поле `deviceId` в профиле).

## 8. Регистрация и вход

При первом открытии показывается страница регистрации:

- приложение **само придумывает** логин (вида `user_ab12cd`) и 5-значный пароль;
- логин можно **отредактировать** до сохранения (3–20 символов: латиница, цифры, `_`, `.`, `-`);
- пароль всегда ровно 5 цифр и **никогда не начинается с нуля** (диапазон 10000–99999);
- кнопка «Показать» копирует пароль, галочка «Запомнить» сохраняет логин **и** пароль в `localStorage`.

Как это работает:

| Что | Где хранится |
|---|---|
| `uid` | выдаёт Firebase при анонимном входе, хранится в его сессии |
| логин | `users/{uid}/uname` + `unameLower` в БД, копия в `localStorage` |
| пароль | **только хеш** в `users/{uid}/passHash`; открытый пароль — в `localStorage`, и только если стояла галочка «Запомнить» |
| соль | `users/{uid}/salt`, 12 случайных hex-символов на аккаунт |
| проверка занятости | `unames/{логин}` через `transaction()` — два человека не получат один логин |
| поиск по логину при входе | точечное чтение `unames/{логин}` (в правилах `.read` стоит на `$uname`, а не на ветке, поэтому перечислить все логины разом нельзя) |

Хеш пароля: `sha256('sh7k:' + salt + ':' + пароль)`. Открытый пароль в базу не попадает
никогда.

**Дальше вводить ничего не нужно.** Пока в `localStorage` лежит логин и включён флаг
`sh_autoacc`, приложение заходит в себя молча: страница регистрации не показывается
вообще. Управление — в **Настройки → 🔑 Мой аккаунт**:

- **«Показать»** — показывает логин и пароль (пароль виден, только если он сохранён на этом устройстве; иначе «— (не сохранён на этом устройстве)»);
- **«Заходить сразу, без ввода пароля»** — включает/выключает тихий вход;
- **«Сбросить запомненный вход»** — забывает логин и пароль на этом устройстве (данные в базе и история сообщений остаются), после чего снова показывается регистрация.

### Вход с другого устройства

На новом устройстве нажми «Уже регистрировался? Войти по логину», введи логин и пароль.
Приложение найдёт `unames/{логин}`, сверит хеш и **перепривяжет аккаунт к текущему
`uid` этого браузера**.

> ⚠️ **История сообщений при этом не переносится.** Она привязана к `uid`, а `uid`
> у нового устройства другой. Старые сообщения и ЛС остаются за старым аккаунтом.
> Об этом прямо написано на странице входа.

### Честно об ограничениях

- **Это не настоящая криптография.** Соль случайная, но медленной функцией (bcrypt/scrypt/argon2) хеш не считается — перебора 90 000 пятизначных чисел на слабом устройстве займёт секунды. Схема рассчитана на «не разбрасывать пароль по чату», а не на защиту от целенаправленной атаки.
- **Логин можно занять, если база доступна на запись.** Анонимная авторизация даёт `uid` каждому, кто открыл сайт, поэтому логин — это идентификатор «через запятую», а не настоящая учётная запись.
- **Пароль хранится в `localStorage`**, если включено «Запомнить». Это удобно, но на общем компьютере его сможет прочитать любой, кто откроет консоль браузера. На своём телефоне — обычное дело, на чужом — отключите «Запомнить».

## 9. Личные сообщения

Кнопка **✉️** в шапке открывает отдельную полноэкранную панель (это не шестая вкладка —
вкладки остались прежними).

- **Список собеседников** — это объединение двух источников: все, у кого в `users/{uid}/homeClass` совпадает `classId` с твоим, и все, кто писал в общий чат твоего класса. Чужие классы не показываются.
- **Поиск** по нику и логину в верхней части списка.
- **Счётчик непрочитанных** — на кнопке ✉️ в шапке суммарно по всем диалогам, плюс отдельная цифра у каждого собеседника.
- **Переписка** — сообщения справа свои, слева чужие, время, кнопка «Назад» и «Escape» возвращают к списку, второй «Escape» закрывает панель.
- Отправка проходит ту же проверку бана/мута, что и общий чат (`HubModeration.checkCanSend`).
- Обновления приходят в реальном времени: подписка на `child_added` / `child_changed` / `child_removed` в ветке `dms/{твой uid}`. Благодаря этому подтягиваются только те собеседники, у которых реально что-то изменилось.
- Подписка включается **один раз при входе** и не отключается при закрытии панели, поэтому цифра на кнопке ✉️ всегда актуальна, даже если панель никогда не открывали. Если uid Firebase ещё не готов, приложение дожидается события `auth-ready` и подписывается сразу после входа.

### Как это устроено в базе

Сообщение пишется **двумя независимыми записями** — по копии каждому из участников:

```
dms/{мой uid}/{uid собеседника}/{key}  -> read: true   (моя копия, я её уже прочитал)
dms/{uid собеседника}/{мой uid}/{key} -> read: false  (копия получателя)
```

Так правила могут закрыть ветку: прочитать `dms/{uid}/{uid собеседника}` может только сам
`uid` или его собеседник, а записать — только они, и только если в поле `from` лежит их
же собственный `uid` (иначе можно было бы подделать сообщение «от» другого человека).
Проверка бана в правилах повторяет ту же, что и для общего чата.

- Список диалогов = содержимое `dms/{мой uid}`.
- Флаг «прочитано» — персональный: у отправителя своя копия всегда `read: true`, у получателя `false` до открытия диалога.

> ⚠️ Если вторая (зеркальная) запись не прошла — например, из-за правил или обрыва связи — отправитель своего сообщения увидит, а собеседник нет. Повторных попыток и явного предупреждения приложение не делает.

## 10. Голосовые сообщения

Кнопка **🎤** есть и в общем чате, и в личных сообщениях.

| Параметр | Значение |
|---|---|
| Кодек | opus, 16 кбит/с, один канал (`audioBitsPerSecond: 16000`) |
| Максимум | 60 секунд (запись останавливается сама) |
| Максимум размера | 150 КБ; более крупный blob не отправляется |
| Формат | `data:`-URL прямо в сообщении (`voice: { url, mime, dur, kb }`) |
| Прослушивание | одна кнопка ▶/⏸ на сообщение, полоса «волны» из 18 делений заполняется по ходу воспроизведения |

- Запись идёт через `MediaRecorder`; приложение перебирает форматы (`audio/webm;codecs=opus` → `audio/webm` → `audio/ogg;codecs=opus` → `audio/mp4;codecs=mp4a.40.2` → `audio/mp4` → `audio/aac`) и берёт первый поддержанный браузером.
- Если `getUserMedia` недоступен или доступ не выдан — кнопка не ломает интерфейс, а показывает тост «Нет доступа к микрофону».
- Во время записи ввод в чат блокируется, кнопка микрофона горит красным; «Escape» отменяет запись.
- Всё воспроизведение в приложении идёт через **один общий объект `Audio`** — два голосовых не играют одновременно.
- Голосовое видно и в поиске по чату (в `data-text` подставляется «голосовое»).

> ⚠️ Голосовые лежат в базе **как текст** (base64), а не в Storage. Плюс — работает без
> отдельной инфраструктуры и мгновенно видно всем. Минус — такое сообщение весит
> десятки килобайт, и ветка `chat` класса растёт заметно быстрее. Если в одном классе
> будет много голосовых, лаги и расход квоты — уже ваши, и дешевле перейти на Firebase
> Storage.
>
> ⚠️ Запись требует защищённого контекста: `https://` или `localhost`. С обычного `http://`
> по IP микрофон не заработает.
>
> ⚠️ Ограничение 150 КБ и 60 секунд — это осознанный компромисс, а не «качество»: на
> 16 кбит/с 60 секунд обычно укладываются в лимит, но на шумной записи могут не уложиться.

## 11. Тема coder20

Третья тема оформления (рядом со светлой и тёмной) — в **Настройки → Оформление**.
Включается и сохраняется как `coder20` в `localStorage` (ключ `sh_theme`), поэтому
старая установка продолжает работать без миграции.

Что она делает:

- **Обесцвечивание.** Вся страница пропускается через `grayscale(1)`, кроме цветных
  точек выбора акцента — иначе палитра была бы нечитаемой.
- **Сдвиг влево.** Контент сужается до `calc(100% - var(--c20-aside))` и прижимается к
  левому краю, справа освобождается колонка. Ширина колонки —
  `clamp(228px, 32vw, 420px)`. На экранах уже 600 px разбивка на две колонки, на узких —
  одна (обычный интерфейс, часы просто не видны).
- **Часы.** SVG-циферблат: внешний круг, 12 делений и дуга, которая обводит долю
  прошедшей минуты. Внутри — `ЧЧ:ММ`, секунды и дата (`26 сентября, суббота`), под
  кругом подпись `coder20`.

Технические детали, из-за которых это работает:

- Фильтр `grayscale` намеренно висит на `html.coder20 body > *`, а **не** на `html` или
  `body`: фильтр на них создаёт containing block и ломает `position: fixed` у модалок,
  тоста и админ-панели.
- Разметка часов (`C20_RING_HTML`) монтируется один раз и в экран входа, и в главный
  экран, поэтому часы видны и до выбора класса.
- Таймер идёт раз в секунду **только** пока активна тема coder20, плюс один перерисовы
  по событию `visibilitychange` — в фоновой вкладке браузер душит таймеры, и без
  этого циферблат отставал бы на минуту.
- `applyTheme()` — одна глобальная функция для всех трёх тем (переключение классов
  `dark`/`coder20`, `meta[name=theme-color]`, старт/стоп часов); та же логика продублирована
  во встроенном скрипте в `<head>`, чтобы при загрузке не было вспышки неверной темы.

## Заметки

- Иконки `icon-192.png` и `icon-512.png` — простые PNG; при желании замените на свои.
- При смене версии приложения обновите имя кэша в `sw.js` (сейчас `school-hub-v10`), чтобы новые файлы подхватились.
- **После изменений в `rules.json` правила нужно опубликовать заново** в консоли Firebase (Realtime Database → Правила → Опубликовать). Файл в репозитории сам по себе на базу не действует. Без новых правил не заработают ЛС и регистрация:
  - `dms/{uid}/{uid собеседника}/{key}` — чтение и запись только для двоих участников;
  - `unames/{логин}` — создать/заменить запись только свою;
  - `users/{uid}/{uname,unameLower,passHash,salt,regAt}` — писать только владельцу `uid`.
- Старые сообщения и ЛС остаются за тем `uid`, под которым были написаны: вход по логину на новом устройстве историю не переносит (см. раздел 8).
- Ник пользователя хранится в `localStorage`, уведомления о «Завтра контрольная» не повторяются для уже просмотренных объявлений.
